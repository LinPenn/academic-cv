# 实验室网站内容编辑器

一个**本地运行的网页版后台**，用来简单、安全地修改实验室网站的内容，不需要懂 Git、YAML 或 HTML。

- 网页界面：表单化编辑 + 右侧实时预览
- 一键发布：提交并推送到 GitHub，网站自动更新
- 安全兜底：只改动你实际修改的字段、自动备份、回收站、写入前校验、构建校验

---

## 一、启动

### Windows

双击项目根目录下的 **`start-editor.bat`**，浏览器会自动打开
<http://127.0.0.1:7788/admin/>

如果编辑器**已经在运行**，再次双击不会重复启动，而是直接打开已运行的那个
（避免同时跑多个实例、各占几百 MB 内存）。

### macOS / Linux

```bash
./start-editor.sh
```

### 用命令行（任意系统）

```bash
node tools/editor/server.mjs            # 默认端口 7788
node tools/editor/server.mjs --port 8899  # 换端口
node tools/editor/server.mjs --no-preview # 不启动预览（更快）
```

> 关闭编辑器：在命令行窗口按 `Ctrl + C`。

**前置条件**

| 组件 | 用途 | 说明 |
| --- | --- | --- |
| Node.js ≥ 18 | 运行编辑器 | 必需，<https://nodejs.org/> 下载 LTS 版 |
| Hugo (extended) | 预览、构建校验 | 项目里已带 `.bin/hugo.exe`；没有也能改内容，只是没有预览 |

## 二、能改什么

| 模块 | 对应文件 | 可以做的事 |
| --- | --- | --- |
| **概览** | — | 看当前状态、快捷入口 |
| **成员与导师** | `content/people/_index.md` | 导师信息（姓名/照片/头衔/研究兴趣/邮箱）、按分组增删学生、调整顺序、批量添加一届新生、自动创建个人主页 |
| **个人主页** | `data/authors/<目录名>.yaml`、`assets/media/authors/`、`content/authors/<目录名>/_index.md` | 每位成员的个人主页：头像、职位、简介、研究兴趣、常用链接（邮箱/GitHub/ORCID…）、所属单位、教育经历；**自定义模块（可调布局）**；可新建与删除 |
| **导师主页** | `content/faculty/*.md` | 个人简介、社会任职、论文列表（逐条编辑 / 批量粘贴 / 搜索）、软著专利、获奖 |
| **新闻动态** | `content/blog/<目录>/index.md` | 发布新闻、上传封面、正文 Markdown 编辑（带工具条）、草稿、删除（进回收站） |
| **论文发表** | `content/publications/<目录>/index.md` | 逐条维护论文：标题、作者、期刊、年份、摘要、PDF 等链接、BibTeX、精选；支持批量新建 |
| **页面文字** | `content/_index.md`、`research`、`join`、`contact` 等 | 首页大标题/主图/简介（不用碰 HTML），其它页面标题与正文 |
| **图片素材** | `static/uploads/` | 拖拽上传、复制路径、删除；自动把文件名改成小写英文 |
| **站点设置** | `config/_default/*.yaml` | 网站名称、标语、简介、配色、明暗模式、导航菜单 |
| **发布到 GitHub** | — | 提交 / 推送 / 拉取、查看构建进度与线上站点 |
| **高级工具** | — | 原文编辑、备份恢复、回收站找回、构建校验 |

## 三、推荐工作流程

1. 左侧选一个模块 → 改内容 → 点右下角 **保存**
   （这一步只写入本地文件，网站还没变）
2. 看右侧 **预览**，确认效果
   （预览会自动刷新；没变化就点预览面板的「刷新」）
3. 点右上角 **校验构建**（可选，约 10 秒）确认没有把站点改坏
4. 点右上角 **发布到 GitHub** → **① 提交并推送到 GitHub**
5. 等 1~2 分钟，GitHub Actions 会自动构建并发布，线上站点即更新
   （点提示里的「查看构建进度」可以看到进度）

> 想先看效果再发布？第 4 步之前的所有改动都只在本机，线上完全不受影响。

## 四、几个常见操作

**加一名新学生**：成员与导师 → 找到对应分组 → `+ 添加成员` → 填姓名、职称、目录名（slug）。
如果勾选了「保存时自动创建缺失的个人主页」，会同时生成
`data/authors/<slug>.yaml`（个人资料）与 `content/authors/<slug>/_index.md`（页面），
姓名与职位会按名单里的内容预填。

**一次录入多名新生**：成员与导师 → `批量添加成员…` → 每行一位，用 `|` 分隔：
`张三 | Ph.D. Student | zhangsan@cau.edu.cn | zhang-san`

**完善某位成员的个人主页**：个人主页 → 点成员卡片 → 填写职位、简介、研究兴趣、链接（邮箱/GitHub/ORCID 等）、所属单位、教育经历 → 上传头像 → 保存。
列表页会提示「头像过大」的成员（页面上头像只显示 160px，建议压到 600×600、300KB 以内，否则会拖慢网页并撑大仓库）。

**新建一位成员的个人主页**：个人主页 → `+ 新建个人主页` → 填目录名（如 `zhang-san`）、姓名、职位 → 可勾选同时登记到成员名单的某个分组。

**给个人主页加自定义模块**（如「我开发的工具」「已发表论文/专利」「项目经历」）：
个人主页 → 进入某位成员 → 「自定义模块」→ `+ 添加模块` → 填标题、选布局 → 添加条目（或 `批量粘贴…` 一次贴入整份清单）。
模块可用 ↑ ↓ 调顺序、复制、删除；改布局不会丢内容。可用布局：

| 布局 | 效果 | 适用内容 |
| --- | --- | --- |
| 列表 list | 一行一条，右侧可放时间 | 论文清单、专利清单 |
| 卡片 cards | 带图/标签的卡片网格（1~4 列） | 自研工具、项目 |
| 时间线 timeline | 左侧竖线 + 时间点 | 经历、获奖、专利授权 |
| 链接按钮 links | 一排按钮 | 软件下载、常用网址 |
| 图片墙 gallery | 图片网格（1~4 列） | 截图、样品照片 |
| 自由文字 markdown | 一段 Markdown | 说明、致谢 |
| 自动列出论文 publications | 自动抓取 `content/publications` 里作者包含本成员的论文 | 不必手工维护 |

每个模块还可以：加副标题、写一段 Markdown 说明、设置是否默认折叠。
模块渲染在「研究兴趣 / 教育经历」下方，由 `layouts/_partials/author_custom_sections.html` 负责。

**加一篇论文到导师主页**：导师主页 → 找到「Publications」分区 → `粘贴导入…` → 选择「插入到最前面」→ 把整段论文列表粘进去。
（每行一条，行首的 `-`、`*` 会自动去掉。）

**发一条新闻**：新闻动态 → `+ 发布新闻` → 填标题/日期 → 先存草稿 → 写完正文和封面后，把「草稿」取消勾选再发布。

**换首页大图**：页面文字 → 首页 → 「首页快速设置」里的 首页主图 → 上传或从素材库选。

**改网站名字**：站点设置 → 站点名称。注意当前显示的是 `hzclab`（模板占位符），建议改成实验室全称。

## 五、安全与可靠性设计

编辑器直接改仓库里的文本文件，所以做了这些保护：

1. **只改你动过的字段**：保存时逐字段比较，未修改的字段（含注释、空行、Markdown 正文）
   字节级保留。在导师主页插入 1 篇论文，git 里就是 **+1 行**，不会把 92 条论文重新排版。
2. **写入前校验**：生成新内容后立即重新解析，逐项核对「写入值 == 读回值」，
   任一不符就**拒绝保存**并报错，绝不留下坏文件。
3. **自动备份**：每次保存前把原文件复制到 `.editor/backups/`（保留最近 60 次），
   可从「高级工具 → 备份」一键恢复。
4. **回收站**：删除新闻、论文、图片时移入 `.editor/trash/`，可恢复，不是真删。
5. **路径白名单**：只能读写 `content/`、`config/_default/`、`static/uploads/`、`layouts/`、`assets/media/`，
   拒绝 `../` 越界。
6. **只监听本机**：服务只绑定 `127.0.0.1`，并拒绝跨站请求与缺少标识头的写入。
7. **构建校验**：`校验构建` 会真正跑一次 Hugo 构建，确认站点没被改坏。
8. **行尾保持**：原文件是 CRLF 就写 CRLF，是 LF 就写 LF，避免整文件 diff。

## 六、GitHub 相关说明（重要）

- 部署链路：`推送到 main 分支` → GitHub Actions 构建（`.github/workflows/deploy.yml`）→ GitHub Pages 发布。
  所以编辑器里的「发布」就是一次 `git commit` + `git push`。
- 站点是**项目站点**，线上地址带子路径：<https://linpenn.github.io/academic-cv/>。
  编辑器预览会保留这个前缀，因此预览里的相对链接和线上完全一致。
- 图片上传的三条规则（都来自 GitHub 的限制，编辑器会自动处理并提示）：
  - 文件名转成**小写英文**：GitHub Pages 跑在 Linux 上，区分大小写；中文和空格会被 URL 编码，容易失效。
  - 单文件 **< 100MB**（编辑器限制 95MB），建议每张图压到 1MB 以内。
  - 图片会进入 git 仓库，长期积累会让仓库变大、克隆变慢。
- 首次推送**会弹出 GitHub 登录窗口**，登录一次即可（凭据由 Git Credential Manager 保存）。
- 如果推送失败，多半是网络访问不了 github.com；此时改动仍已提交到本地，稍后重试即可。
- 别人（或你在别处）推了新内容时，「发布」面板会提示先 **拉取远端更新**。

## 七、常见问题

**打不开 / 端口被占用**：编辑器会自动换到 7789、7790…，**请以命令行窗口里显示的地址为准**
（`打开：http://127.0.0.1:xxxx/admin/`）。不要凭记忆直接输 7788。

**页面出现「编辑器载入失败」**：页面会把具体原因写在上面（脚本错误 / 请求超时 / 8 秒未载入）。
常见原因是编辑器服务没在运行、或浏览器插件拦截了本站脚本。先确认命令行窗口还开着且没报错，再刷新页面。
如果是「脚本错误」，说明前端 JS 有语法问题，可运行 `node tools/editor/test-boot.mjs <端口>` 定位。

**右侧预览打不开**：点预览面板的「刷新」；仍不行就在概览页点「启动预览」。
若提示找不到 hugo，把 `hugo.exe` 放到 `.bin/` 目录，或安装到系统 PATH。

**保存时提示「front matter 无法解析」**：说明这个文件的 YAML 写法超出了编辑器的安全范围，
请改用「高级工具 → 原文编辑」手动修改（保存时同样会校验）。

**改错了想撤销**：高级工具 → 备份 → 找到对应文件点「恢复」。
或者用 git：`git checkout -- <文件路径>`。

**预览里看不到刚发布的新闻**：草稿状态的内容不会发布到线上，本地预览是能看到的；
检查是否忘了取消「草稿」。

## 八、目录结构

```
tools/editor/
├─ server.mjs            # HTTP 服务：JSON API + Hugo 预览代理 + 静态界面
├─ lib/
│  ├─ yaml.mjs           # 轻量 YAML 子集解析/生成（带行号区间）
│  ├─ frontmatter.mjs    # 文档模型：只改写变化的字段，含写入校验
│  ├─ site.mjs           # 各内容模块的读写逻辑（成员/导师页/新闻/论文/页面/设置）
│  ├─ store.mjs          # 路径安全、备份、回收站、图片上传
│  ├─ git.mjs            # git 状态 / 提交 / 推送 / 拉取
│  ├─ hugo.mjs           # hugo server 代理与构建校验
│  └─ diff.mjs           # 保存前差异预览
│  └─ profiles.mjs       # 成员个人主页（资料 + 头像 + 自定义模块）
├─ public/               # 网页界面（零依赖原生 JS）
│  ├─ index.html / style.css
│  └─ js/core.js, js/app.js, js/modules/*.js
├─ test-roundtrip.mjs    # 自测：所有内容文件能否安全回写
├─ test-api.mjs          # 自测：API 端到端（改完自动还原）
└─ test-ui.mjs           # 自测：界面代码渲染 + 保存往返
```

本地运行产物（不会提交到 GitHub）：`.editor/backups/`、`.editor/trash/`。

## 九、维护者：自测

改完编辑器代码后跑一遍（需要服务已启动）：

```bash
node tools/editor/test-roundtrip.mjs          # 离线：101 个内容/资料文件回写安全性
node tools/editor/server.mjs                  # 启动服务（另开一个窗口）
node tools/editor/test-boot.mjs 7788          # 前端 JS 语法自检 + 启动流程复现
node tools/editor/test-api.mjs 7788           # 123 项接口测试（含渲染验证，自动还原改动）
node tools/editor/test-ui.mjs 7788            # 37 项界面集成测试
```

> `test-boot.mjs` 会先把 `public/js` 下每个文件真正解析一遍再模拟浏览器启动，
> 专门用来防「某个 JS 写坏了 → 整页白屏却看不出原因」这类问题
> （前端 JS 有语法错误时，页面整段脚本都不会执行，只剩超时提示）。

`test-roundtrip.mjs` 会对 `content/`、`config/`、`data/` 下每个 Markdown/YAML 文件做
「解析 → 原样回写 → 校验」，任何字段写出后读不回原值都会报错；
新增内容文件后建议跑一次，确认新写法在编辑器的支持范围内。
